    Контракты, JSON и идентификаторы¶

    Графовая схема¶

    Фактический экспорт graph_engine.py:

    {
  "schema": "keum.graph.v1",
  "preset": "kathara",
  "seed": 0,
  "complexity": 2,
  "units": "normalized",
  "source_status": "symbolic reconstruction",
  "nodes": [
    {
      "id": "K1",
      "position": [0.0, -4.5, 0.0],
      "kind": "signet",
      "entity_id": 21,
      "label": "1",
      "group": "base"
    }
  ],
  "edges": [
    {
      "source": "K1",
      "target": "K2",
      "kind": "connection",
      "weight": 1,
      "group": "base"
    }
  ],
  "annotations": [],
  "metadata": {
    "entity_id": 21,
    "coordinate_system": "right-handed; z-up"
  }
}

    Инварианты¶

    • schema должен совпадать с keum.graph.v1.
    • nodes[].id уникальны.
    • position — ровно три конечных числа.
    • edges[].source и edges[].target существуют.
    • В базовой реализации самопетли запрещены.
    • entity_id ссылается на рабочий реестр; его семантическая правильность требует проверки.
    • source_status не должен выдавать эвристическую модель за точную оцифровку.

    Версионирование¶

    При изменении структуры рекомендуется новая версия схемы, например keum.graph.v2, и миграция данных. Изменение только геометрии пресета не требует изменения версии контракта, но должно отражаться в changelog.

    Безопасность¶

    SVG генерируется с XML-экранированием строк. При загрузке произвольных SVG от пользователей необходима санитарная обработка, поскольку SVG может содержать активное содержимое. Для публичного веб-приложения запрещено доверять произвольным URI из JSON.
